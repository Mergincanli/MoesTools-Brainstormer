## j01-ra1: ra1.allied.spy, ra1.soviet.attack-dog

### ra1.allied.spy

12 hesitations, 1 gaps.

- **abilities**: chose Four entries: Disguise (passive, disguise), Infiltrate (active, capture-structure; its summary gives every building's result, including the Radar Dome's shared view), Sonar Pulse (active, reveal-area) and Parabombs (active, bombard-area); alternatives Fold the Sonar Pulse and the parabomb strike into the Infiltrate entry, which links only capture-structure; Keep them as separate entries but also link capture-structure on them. The task asks for the infiltration results as capture-structure sabotage, including the sonar pulse and parabombs. But abilities[] says one entry per button, and the earned powers are sidebar buttons of their own. Under Pattern links, pressing them gives a reveal or a strike, not a building takeover. So capture-structure stays on the Infiltrate button that earns them.
- **abilities.cooldown**: chose per-life; alternatives no cooldown (an instant order). Cooldown bands say an instant order with no wait has no band, but per-life means one use per life or purchase. The spy is used up by entering, so there is exactly one use per purchase. The rule does not say which wins for an action that spends the unit.
- **abilities.cooldown**: chose per-life; alternatives long (recharging); left out (no figure). The rule is clear; the sources are not. The Sonar pulse page says single use. EA's code grants the spy's pulse as a recharging power, and Remastered patch 740600 fixed it being usable only once. I followed the wiki for 3.03, as the Ore Truck precedent does, and added an uncertain entry with sources_disagree.
- **abilities.kind**: chose active (also abilities/3), source innate; alternatives triggered (granted when the spy gets in); source commander-power. The grant happens on an event, but the player then presses the button and picks a spot. The registry note says what a spy earns belongs to the spy and that no RA1 ability has source commander-power.
- **confidence**: chose medium; alternatives high. Official manual text is quoted on the Spy page, which alone would give high. The High-or-Medium tie-break drops to medium when a contradicted point decides a band, and the sonar pulse dispute decides abilities/2's cooldown band. It is unclear whether this is a real contradiction or only a Remastered change, because the code is the Remastered release.
- **roles.secondary**: chose ["scout"]; alternatives [] (leave empty); siege (from the parabombs). Scout's requirement is met through the disguise pattern's stealth-deception category. It fits through the Radar Dome's shared view and the sonar pulse, which are buttons every copy has (step 2). Siege's requirements need a weapon part (drop or lobbed delivery, or long range), and the spy has no weapon. It also did not seem to fit the unit's job, so I added no fit_note.
- **sensors.traits**: chose []; alternatives stealth. The rule is clear: the registry gives the spy's disguise to the disguise pattern, and stealth means being hard to see. The spy is in plain view, only mistaken for a friendly unit.
- **countered_by**: chose mobility-trait:crush; alternatives class:vehicle. Matchups step 1 names the enemy by what wins. The Spy page says AI vehicles sometimes run spies over, and running over infantry is the crush trait, not every vehicle.
- **counters**: chose mobility:naval-submerged plus unit:ra1.soviet.submarine; alternatives add target:structure-like links for fake buildings or production (no such unit kind). Counters must describe units. The spy's other wins are against buildings, which no link kind covers, so only the sonar pulse's submarine counter is listed.
- **weaknesses**: chose armour-class:unarmoured (with having no weapon named in the reason); alternatives leave the lack of a weapon out of weaknesses. Matchups step 5 says to hang something the unit lacks on the part that causes it. An unarmed unit has no weapon part to hang it on, so it went on its fragility.
- **sources.kind**: chose official (EA's GitHub source release; the same for TECHNO.CPP on the dog); alternatives database. Source kinds lists the publisher's own site and in-game text under official and data-mined values under database. Released source code is between the two.
- **combos**: chose [] (and [] for the dog); alternatives unsourced pairings such as spy plus engineer, or dogs beside base defences. No page read names a combination, and Matchups asks for sourced reasons.

Gaps (no term fitted well):

- **abilities.patterns**: used capture-structure; wanted possibly a separate 'spy on a structure' pattern. No fit_note was written, because 'sabotage it from inside' plus the infiltration category cover it acceptably. Still, most of the spy's results are intelligence (production, power, ore, the shared radar view), not takeover or damage.

### ra1.soviet.attack-dog

10 hesitations, 2 gaps.

- **armament.range**: chose melee; alternatives medium (the reach is about three quarters of the rifle's, inside 0.7 to 1.5). The melee coding rule and the Melee-or-Short tie-break count a unit's own leap as melee. The code shows the dog leaping to its victim. The infobox figure would band medium.
- **armament.delivery**: chose melee; alternatives ram; attach. The code takes the dog off the map while it leaps and puts it back on the hit, so the dog itself flies at the target. Ram means hitting by collision and usually self-destruction; the dog survives and mauls. Melee covers strikes or lunges at touching distance.
- **mobility.speed**: chose medium (speed_raw 1); alternatives fast (the code doubles its pace whenever it has a target). Speed bands count an unlimited sprint but do not cover a speed that applies only while chasing a target. speed_raw uses the plain land speed figure.
- **sensors.traits**: chose ["detector"]; alternatives [] with a fit_note. The task and the registry say detector. But the term means revealing for the whole team, and the sources only show the dog seeing through spies itself. I added a fit_note.
- **roles.secondary**: chose ["scout"]; alternatives []. Step 4 allows scout from a sensor trait with an in-game basis. Whether spotting spies fits scout's 'finds, spots and marks enemies' is a judgement. The Kennel's 'scout infantry' line is the wiki's own words, so it does not count.
- **countered_by**: chose weapon:small-arms (plus unit:ra1.shared.rifle-infantry); alternatives role:anti-infantry; class:infantry. The source names only a unit (Rifle Infantry). Matchups step 1 then reads what makes that unit win, and here it is its quick rifle burst.
- **counters**: chose weapon:flamethrower and weapon:explosives (counters/4), for the Flamethrower Infantry and Grenadier; alternatives class:infantry; unit: links to those soldiers. The wiki names units and says their slow shots are why they lose. I took each unit's weapon family. The Grenadier's family (explosives) is my reading, since that unit is not researched.
- **counters**: chose role:infiltrator (spies and thieves) and role:engineer; alternatives pattern:disguise; class:infantry. The manual names Engineers, Spies and Thieves, which are units. Matchups step 1 reads them by their job first.
- **weaknesses**: chose weapon:blades (infantry only, one dog per victim); alternatives range:melee; delivery:melee. Matchups step 5 says to hang the gap on the part that causes it. The bite's limits belong to the weapon itself.
- **strengths**: chose tier:t1; alternatives leave the low price out. No link kind exists for price. I followed the Terror Drone sample, which uses tier:t1 for being cheap.

Gaps (no term fitted well):

- **armament.patterns**: used none (empty list); wanted execute-target. No registered pattern covers an attack that kills one kind of target outright, whatever its health, while it cannot touch any other kind.
- **sensors.traits**: used detector; wanted a detector that sees through disguises for itself and attacks them, without unmasking them for the team. Recorded as a fit_note on the unit.

### Unclear rules (8)

- **Earned one-shot powers**: Nothing says how a side-wide one-shot button that a unit earns (the Spy's Sonar Pulse and parabombs) is counted. Is it an ability of the earning unit, and which kind and source does it take (active or triggered, innate or commander-power)? The registry says only that it belongs to the Spy.
- **Cooldown of an action that uses up the unit**: Cooldown bands say instant orders have no band, while per-life means one use per life or purchase. For an infiltration or capture that removes the unit, either reading fits.
- **Speed only while chasing**: Speed bands handle sprints limited by a meter but not a pace the engine gives only while the unit has a target (the dog runs at double speed while chasing).
- **Detector scope**: The detector term says it reveals hidden enemies for the whole team. Several units (this dog, and possibly the RA2 and RA3 dogs) only see through a disguise themselves and attack. There is no term for 'sees through for itself'.
- **Released source code as a source**: Source kinds do not say whether EA's GitHub code release is official or database. Nor do they say whether it counts as official text that 'settles' a contradiction under the confidence tie-break. The registry relies on it for engine behaviour but follows wiki pages over it in places (Ore Truck).
- **Version contradiction against Remastered**: The confidence tie-break does not say whether a disagreement that may only be a Remastered change counts as sources contradicting each other. Here the code and patch notes are from the Remastered Collection and the wiki claim is version-unspecified. I treated it as a contradiction and dropped the spy to medium.
- **Weakness of an unarmed unit**: Matchups step 5 says to hang a missing part on the part that causes it. An unarmed unit has no weapon part, so it is unclear where 'no weapon' goes.
- **Where to note faction facts**: Source units have no general notes field. The task asked to note that the Soviet Spy is campaign-only, and I put it in tier.basis.

### Unclear rules (8)

- **Shared units whose stock parts differ by side**: The rules give no way for a shared entry to code a part that changes with the owner's side, such as the minelayer's mine type: the roles, the ability's effect, and matchups that only hold for one side. Registry choice 6 also does not list the minelayer as shared, while the brief fixes a shared id.
- **Cooldown of a multi-charge stock refilled only at a resupply point**: 'Comes back only at a resupply point' (per-life) and 'held back only by a stock' (no band) overlap. Per-life's own definition says 'one use'.
- **can_target step 1 versus naval's coding rule**: For a weapon that does no damage, step 1 lists only the kinds the sources name, while naval's rule lists naval on every weapon that lists ground-vehicle. It is not said which rule wins for a repair tool.
- **Official text that disagrees with the infobox, and confidence**: The confidence tie-break covers established sites that contradict each other with no official text to settle it. It does not say what happens when official manual grades (armour None, 'slow') contradict the infobox that the registry tells us to code from.
- **Counters for a support unit that cannot fight**: counters requires at least one entry, so an unarmed repairer must get a derived entry that no source names.
- **'Third page of the same site'**: It is unclear whether a manual scan hosted as a cnc.fandom File page counts as a page of that site, and whether a site the registry codes as kind guide (StrategyWiki) counts as an 'established site' for this rule.
- **Crush on medium vehicles**: The registry lists crushers (APC, both minelayers, Radar Jammer and others) that the size rule then excludes from the trait. Neither the registry nor the trait says whether to record them through a fit_note.
- **Weapon in the brief versus the field rules**: The brief says the Field Mechanic 'has no weapon', but the field rules (attack-order weapon, damage_map Mechanical to repair, support's requires) make his wrench a weapon entry.
